# Issues — open work

Open defects only; closed rows are **deleted** — recover with `git log --grep 'fix(P-xx)'` (`P-36` is the exception: #27's merge message omitted the id, so its two lessons live in the rules instead). Numbers are never reused or renumbered; merged rows keep every number they absorbed. Highest number ever issued: **P-73**. Reserved — cited by source or by an earlier row, never written up: P-20, P-48, P-54, P-55, P-59, T-23, P-73.

**Rules**
- **Warnings are the maintainer's call** — options named, never a blocker, never grounds for a public API change. Fix, suppress or ignore is yours. Baseline **6**, all `CS8600` at `GdalConfiguration.cs(60,33/50/69)`: a NuGet content file copied into each GDAL-consuming project's `obj/`, hence two copies (P-61). Nothing in this repo's own source warns. A **third GDAL-consuming test project** copies it a third time and moves the baseline to **9** — which is why reprojection tests live in `Io.Tests`.
- `Guard` is the only evidence field; `none` means a fix could land and revert green. **A behaviour change with no test asserting the observable result is not closed.** If the guard is hard to write, the method's visibility is the bug (P-02).
- **The case total is the diff that matters** (CI prints none) — but it only proves nothing was *lost*: #26's migration held the total while two tests went red, and a duplicated `[Fact]` in a second class *raises* it. Clean-build before reading either.
- **A number-valued claim needs a run, not a derivation.** `∞ - ∞` is `NaN` and `4 - ∞` is `-∞`, and *which* one you get is decided by a guard two frames up in the callee. Three such claims shipped in `BoundingBox`'s XML docs and one died in a theory row on first execution. #29 shipped three more in `FeatureAreaTests` doc comments about deleted code; the digits were deleted rather than confirmed.
- **Assert the externally determined answer.** Never pin a value §0 leaves open. No commented-out guards. **A test's data is part of its claim**, and a guard whose precondition lives in a fixture can be retired by a fixture cleanup — build the state in the test. **A default argument is part of that data**: renaming a parameter that carries one can flip its polarity, and every call site that omitted the argument changes fixture while staying green — #29 did exactly that in a comment-only commit. A bare `Assert.True(x)` that fails prints `Expected: True / Actual: False` and nothing else; pass the value as the message. **An assertion must belong to its test's claim** — one that a reader cannot derive from the doc comment above it is unfindable and unfixable when it fails.
- Deleting dead code beats annotating it; causing a defect to disappear beats testing around it. A sentinel you must compare against to detect is the defect; **so is a comment that contradicts the line under it** — three were live at once in #27. **So is a doc comment that contradicts itself** two paragraphs later: #31 appended a correction instead of replacing the claim, and shipped a duplicated sentence and a stray `///` with it.
- **Copy verbatim or don't move.** Same-named builders with different return types (`Features` vs `CrsInfo`) are two members, not one: a suffix that distinguishes them is load-bearing. A private helper's name resolves through its containing class, so "delete the duplicate" can mean "delete the callers' only reference". A test move is one commit — split the add from the delete and the copies survive.
- **An invariant of a type belongs on the type.** #28 answered §0's box-model question in `BoundingBox.cs`'s XML docs and the answer held; a `CHANGES_*.md` is the first thing a reader of the file never opens. This rule replaces that row. **A private helper's comment is not the type** — the axis-order guarantee is documented on `CreateSpatialReference`, where nobody looking for the guarantee would read.
- A row over ~6 lines is a design question: `CHANGES_*.md`, link it, keep the row. No CI state, no annotation counts, no "verified at `<sha>`".
